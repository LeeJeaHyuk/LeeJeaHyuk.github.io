[이전 글](/ai/decision-model-economics/)에서 이어서, 그다음에는 곰곰이 생각해보니 게임을 더 살아 있는 것처럼 보이게 하는 방법으로 이 모델이 생각보다 큰 역할을 할 수 있을 것 같다는 생각이 들었다. 게임은 기업이 아니더라도 모델 훈련용 데이터를 얻기 쉬울 것 같고, 기존 상호작용도 이동이나 공격, 회피처럼 행동을 결정하는 부분이 많아서 결정 모델을 적용하기도 쉬워 보였기 때문이다. 하지만 직접 적용해보려고 했을 때 생각만큼 막 아무 곳에나 적용할 수는 없었다.

기술 설명은 [개념 정리](/ai/jev-system-one-decision-model/), 실제 사용한 모델과 실행 결과는 [Minecraft Agent Lab 실험 기록](/ai/minecraft-agent-lab-experiment/)에서 볼 수 있다. 다른 모델과 사례를 찾아본 내용은 [자료 조사](/ai/decision-model-references/)에 정리했다.

Minecraft Agent Lab에서는 Qwen이 계획을 세우고 Kev가 현재 상황에서 할 행동을 고르도록 했다. 나무를 모으다가 몬스터가 나타나면 대응하고, 그 뒤에 하던 일을 다시 이어가는 식이다.

그런데 행동을 고르는 것 외에도 처리할 일이 있었다. 몬스터에게 맞으면 모델의 답을 기다리기 전에 로컬 코드에서 하던 동작부터 멈춰야 했고, 위협에 대응한 뒤에는 이전 작업이 어디까지 끝났는지 확인해야 했다. 채집이 타임아웃됐는데 실제 재고에는 원목이 들어온 경우도 있었고, 중단된 사냥을 끝난 것으로 판단하는 부분도 수정해야 했다. 결정을 모델에 맡겼다고 해서 이런 실행 쪽의 문제까지 없어지는 것은 아니었다.

밤에 원목을 모아 판자를 만들고 집으로 돌아오는 실행은 됐고, 좀비에 대응한 뒤 중단됐던 귀가를 이어간 경우도 있었다. 하지만 크리퍼에게 피해를 입었고, 다른 작업을 준비할 때는 사망 후 장비를 회수하거나 시간과 주변 적을 조정하기도 했다. 잘된 장면 몇 개만 보고 모델이 혼자서 계속 살아남을 수 있다고 보기는 어려웠다. 게임에서 데이터를 모을 수 있다는 것과 그중 어떤 선택이 좋았는지 정하는 것도 따로 생각해야 할 부분이었다. 단순한 판단은 기존 코드로 처리하는 편이 더 나을 수 있고, 게임과 모델을 함께 돌리는 자원 부담도 있어서 생각했던 것처럼 모든 판단에 바로 넣을 수 있는 것은 아니었다.

판단이 빨라지는 게 실제 작업에서도 얼마나 차이를 만드는지는 따로 봐야 할 것 같다. 게임에서는 이동하고 나무를 캐고 아이템을 줍는 시간도 걸려서, 모델이 답하는 시간만 줄어든다고 전체 작업이 그만큼 빨라질까 하는 고민도 있다.
